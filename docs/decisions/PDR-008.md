# PDR-008: Occasional independent review via a raw Claude API call

**Date**: 2026-09-07
**Status**: Accepted

## Decision

Add `training/third_party_review.py` — a manually-invoked, occasional tool
that sends the training code and corpus to a completely fresh Claude API
call (model: Claude Fable 5.1, `claude-fable-5-1`) for an independent
review, using the product owner's own prepaid Anthropic API key. This is a
**third opinion**, separate from and in addition to this project's two
standing AI collaborators (Claude as engineering lead, Gemini for dataset
generation and, since today, engineering-proposal review and blind
adversarial re-review via `review_bridge/` — see
[PDR-006](PDR-006.md)'s amendments). It is not a standing automated
process — the product owner's own framing was "just a once in a while
thing I invoke if it proves worth it."

## Reasoning

### Why not reuse an existing mechanism

Two mechanisms already do something adjacent, and neither fits:

- **A fresh Claude Code session** (how the 2026-09-02 external
  training-core review was actually run, per that review's own header:
  *"a separate Claude Code session with no prior context on this project,
  working from a fresh clone"*) — this worked well and caught real
  findings (C1-C4, M5-M11), but the product owner specifically wants
  direct control over model choice, prompt content, and cost via his own
  API key, rather than however a Claude Code session gets commissioned.
- **The Claude<->Gemini review bridge** (`review_bridge/`) — a standing,
  cumulative relationship (the same Antigravity session accumulates
  context across engineering-proposal rounds), not a fresh one-shot
  review. Reusing it for this purpose would reintroduce the same
  correlation-bias risk PDR-006's 2026-09-07 amendment just moved
  adversarial re-review away from.

A genuinely fresh, zero-context, one-shot API call is a third kind of
check this project didn't have a mechanism for yet.

### Scope and exclusions

The bundle sent (`training/*.py` + `requirements.txt` +
`datasets/synthetic.jsonl` + `datasets/real_validation.jsonl` +
`docs/datasets/*.md` + `docs/decisions/*.md` + `docs/vision/*.md` +
`training/COST_LEDGER.md`) mirrors the 2026-09-02 precedent review's own
practical scope. Two exclusions are not judgment calls:

- **`datasets/real_holdout.jsonl` is categorically excluded** — sealed,
  never touched for routine work per `DATASET_SPEC.md`. Including
  `real_validation.jsonl` (the 15-record routine-eval real tier) was a
  direct decision by the product owner, made explicitly, not a default.
- **`review_bridge/`'s current content is excluded** — ephemeral,
  gitignored, not meaningful review material.

**`docs/reviews/*.md` (prior review reports, including the 2026-09-02
precedent and this session's own copy-ratio disposition docs) is
deliberately excluded**, co-drafted with Gemini on the review bridge
before the first real run: the whole point of paying for a from-scratch
pass is genuine freshness. Including past findings risks anchoring the
reviewer on already-settled conclusions — either rubber-stamping them or
re-litigating them as if new — which defeats the purpose of a third,
independent check.

### Execution boundary and authorization

Claude Code (this session) invokes the real, billed call directly, on the
product owner's explicit "go ahead" each time — the same authorization
pattern already governing every Gemini MCP call (see
`AI_COLLABORATION.md`'s "Financial guardrails"). The API key is retrieved
at runtime from Windows Credential Manager via Python's `keyring` package
(target `ANTHROPIC_API_KEY`, username `Fable Review`) — it is never typed
into a conversation, command, or committed file, and this script accepts
it no other way (verified: `keyring.get_password(...)` retrieves it
correctly; confirmed live 2026-09-07).

A free `count_tokens` step always runs before any real call and prints an
exact input-token count plus a cost table across all four current models
at several output-size assumptions — no spend happens on an estimate.
`--dry-run` and `--run` are mutually exclusive, explicit flags; there is
no default that spends money.

### Model and cost

Claude Fable 5.1 was chosen directly by the product owner for the first
run, over the cheaper Opus 5/Sonnet 5 (this skill's own default guidance
is to reach for Opus 5 unless Fable is explicitly requested) — deliberate,
not a recommendation either collaborator made unprompted. Real cost at the
first dry run (2026-09-07, 339,395 input tokens against the then-current
532-record corpus): **$3.89-$6.39** depending on output size, well within
the product owner's prepaid budget tolerance.

### Report format and downstream handling

Output is written to `docs/reviews/<date>-claude-api-review.md`, matching
the 2026-09-02 precedent's header convention exactly (Reviewed / Scope /
Reviewer / Verification level, findings labeled
`[VERIFIED]`/`[ESTIMATED]`/`[UNVERIFIED]`) plus a required Recommended
Action per finding (added during prompt co-drafting with Gemini, since
this reviewer gets exactly one shot with no follow-up round, unlike the
Claude<->Gemini bridge's iterative alignment). Findings get verified and
dispositioned through the same existing review-to-fix workflow the
2026-09-02 review used — this is a new *source* of findings, not a new
process for handling them.

## Scope

- A one-off, manually-invoked tool, not a scheduled or automated process.
- Applies only to `training/third_party_review.py`'s own bundle — does not
  change what gets sent to Gemini (generation) or the review bridge
  (engineering proposals).
- `docs/reviews/*.md`'s exclusion from the bundle is specific to this
  tool's stated goal (maximum freshness on a paid, one-shot pass); it does
  not imply those documents are unimportant elsewhere.
- Revisit if a run's findings suggest the tool isn't earning its cost, or
  if the product owner wants a different model/cadence going forward.

## Approved by

- Product Owner — chose to build this tool, picked Fable 5.1 for the first
  run, decided to include `real_validation.jsonl`, chose the execution
  boundary (Claude Code invokes it directly), and provided the Windows
  Credential Manager entry, 2026-09-07.
- Engineering Lead (Claude) — verified the credential retrieval live
  before writing any code that depends on it, ran the free dry-run to
  confirm real token counts and cost rather than estimating, and reused
  this project's existing financial-guardrail and review-doc conventions
  rather than inventing parallel ones.
- Gemini (review bridge) — co-drafted the review prompt directly,
  recommended excluding `docs/reviews/*.md` (independently reaching the
  same conclusion as Claude's own lean) and adding the Recommended-Action
  and intentional-overlap preemption to the prompt.
