# PDR-004: Claude + Gemini tooling integration — MCP server selection and guardrail redesign

**Date**: 2026-08-19
**Status**: Accepted

## Decision

Use **`rlabs-inc/gemini-mcp`** (MIT license) as the MCP server wrapping the
Gemini API for Claude-to-Gemini tool calls, configured via a project-scoped
`.mcp.json` with the API key supplied through an environment variable —
never committed. No standalone Gemini CLI or Antigravity dependency.

Financial guardrails are redesigned around two facts verified live during
this investigation (not assumed):
1. Google now enforces **mandatory, hard project-level and account-tier
   spend caps** on the Gemini API (effective 2026-04-01) — once a project's
   monthly cap is hit, further calls are blocked platform-side, with roughly
   a 10-minute enforcement delay.
2. A maintained MCP server/SDK absorbs the wire-format correctness burden
   (request building, response parsing) that the predecessor project's
   hand-rolled HTTP layer had to self-verify via hash-pinning and diagnostic
   gates.

Given both, this project keeps **financial/authorization guardrails in
full** but retires the **wire-format verification ceremony** the
predecessor project needed for its hand-built HTTP layer.

## Reasoning

### Server selection

Three community options were evaluated, per the candidates named when this
fork was planned:

| Server | Transport | License | Activity (checked 2026-08-19) | Fit |
|---|---|---|---|---|
| `jamubc/gemini-mcp-tool` | Wraps Gemini CLI, which Google retired 2026-06-18; now defaults to Antigravity CLI | — | — | **Rejected** — exactly the "Gemini CLI alongside Claude Code" pattern this project's plan explicitly avoided. |
| `raydollete/gemini-for-claude-mcp` | Vertex AI (Google Cloud SDK, service-account/ADC auth, requires `roles/aiplatform.user` IAM role) | Apache 2.0 | 0 stars, 0 forks, 8 commits | Direct-API, but Vertex AI's GCP-project/IAM setup is heavier than this solo project needs, and low community activity means less confidence in ongoing maintenance. |
| `rlabs-inc/gemini-mcp` | **Gemini API directly** (`GEMINI_API_KEY` from Google AI Studio) | MIT | 215 stars, 44 forks, 41 commits | **Selected.** Direct API (not CLI-wrapped), simplest auth (a single API key, no GCP project/IAM setup), most community traction and activity of the three, permissive license. |

`rlabs-inc/gemini-mcp` also exposes 37+ tools beyond plain text generation
(image/video, web search, document analysis, code execution) — more surface
than this project needs today, but no cost to having it available, since
guardrails gate spend, not tool count.

### Guardrail redesign

The predecessor project's `gate5_pre_execution_attestation_template.json`
(read directly, not assumed) bundled two genuinely different concerns:

1. **Financial/authorization safety** — cost ceilings, explicit human
   sign-off before a real, billed call, cost reconciliation after. **Kept in
   full.** Billing is real and per-token regardless of transport; an MCP
   server doesn't change what a call costs or who's responsible for
   authorizing it.
2. **Wire-format correctness verification** — request/response hash-pinning,
   endpoint/field confirmations, schema-drift diagnostics. **Retired.** This
   ceremony existed specifically because the predecessor pipeline hand-built
   raw HTTP against the Gemini API with no local schema guarantee — a
   maintained MCP server carries that correctness burden in its own test
   suite instead.

### Concrete guardrail for this project going forward

For small, interactive, exploratory Gemini-via-MCP calls inside a normal
Claude session: no full attestation JSON. Instead:
- A lightweight running cost ledger (a plain log of what was spent, when,
  on what).
- Explicit confirmation from the product owner required before any call
  expected to exceed a small per-call/session threshold — to be set when
  real generation work begins, not speculatively here.
- Google's platform-level spend cap (set in AI Studio, per project) as a
  hard backstop underneath the above, not a replacement for it — the
  10-minute enforcement delay means an unauthorized burst could still incur
  some real cost before the cap engages, so explicit sign-off before a call
  remains the primary control, not the cap.

## Verification log

- **2026-08-19**: Gemini MCP connection tested live end-to-end — asked
  Gemini (`flash` model) to say hello and confirm it was working; it
  responded confirming it was functioning correctly. Connection confirmed
  working. (The `pro` model's default alias 404'd server-side, pointing to

## Scope

- Applies to Gemini API usage for dataset generation once that work begins.
  As of this PDR, the only live Gemini call made under this repository is
  the connectivity test above; no dataset-generation call has been made.
- `.mcp.json` is committed with a placeholder/env-var reference for the API
  key, never a literal key. Actual key storage is the product owner's local
  environment, outside version control.
- Revisit this PDR if `rlabs-inc/gemini-mcp`'s maintenance activity changes
  materially, or if Google's spend-cap mechanics change from what was
  verified 2026-08-19.
