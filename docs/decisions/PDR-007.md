# PDR-007: Separate model-selection set from real-tier reporting

**Date**: 2026-09-07
**Status**: Accepted

## Decision

`train.py`'s checkpoint selection (`load_best_model_at_end`,
`metric_for_best_model="eval_loss"`) now evaluates against a selection-only
slice carved out of `datasets/synthetic.jsonl` (+ any consolidated gold
releases), not against `datasets/real_validation.jsonl`. The real tier is
removed from the training pipeline entirely and stays reserved for
`evaluate_real.py`'s independent, untouched reporting run.

The slice is carved by deterministic content-hash bucketing
(`prepare_data.is_in_selection_slice`, keyed on `sha256(input)`, target
10% of the pool) rather than a stored index list or a random seed — a
record's train/selection membership depends only on its own text, so it
doesn't shift as the corpus grows or gets reordered, and there's no
separate seed file that can drift out of sync with the data the way
`split_real_holdout.py`'s recorded-seed approach requires upkeep for.

## Reasoning

An external review (2026-09-02,
[`docs/reviews/2026-09-02-training-core-review.md`](../reviews/2026-09-02-training-core-review.md),
finding C3, `[OWNER CALL]`) found that `train.py:140`'s
`load_best_model_at_end=has_val` selected checkpoints on the same 15
records in `real_validation.jsonl` that `evaluate_real.py` then reported as
"the generalization check this project's real tier exists for." Once a
checkpoint is chosen on a set, results on that set stop being a
generalization estimate — two distinct problems:

- **Bias**: best-of-8-epochs on `eval_loss` fits the checkpoint choice to
  those exact 15 records.
- **Noise**: 15 examples is a loud selection signal; epoch-to-epoch
  `eval_loss` ordering at that size is substantially chance.

The review offered three options and reserved the choice to the product
owner rather than resolving it unilaterally, per this project's own
governance model for `[OWNER CALL]` findings:

- **(a) — adopted**: carve a selection-only slice out of `synthetic.jsonl`,
  keep the real tier untouched for reporting.
- (b) keep selecting on the real set but drop the generalization claim from
  `evaluate_real.py`'s docstring and report it as a fitting curve.
- (c) revert to last-epoch and state overfitting is unmanaged at this
  corpus size.

The product owner chose (a). He also asked whether the real 15 could
instead be split in two — one half for selection, one for reporting — and
that was answered no: at 15 examples, splitting makes both halves noisier
than the review already says 15 alone is. Revisit that question if the
real tier grows past roughly 50 examples.

The sealed 12-record `real_holdout.jsonl` was not considered for this role
— `DATASET_SPEC.md` already reserves it for declared release milestones
only, and using it for routine per-run selection would burn the one
instrument this project has that nothing else has touched.

## Consequence for `real_validation.jsonl`

No longer read by `prepare_data.py` for anything other than a schema
hygiene check (so a malformed real note is still caught early). Not
written into `training/prepared/`. Not evaluated against during training.
Used exclusively by `evaluate_real.py`, unchanged, which already read it
directly from `datasets/` rather than through `prepared/` — so this fix
required no changes to that script at all.

## Scope

- `training/prepare_data.py`: `resolve_source_files()` now returns only
  `synthetic.jsonl` + gold releases; `is_in_selection_slice()` /
  `split_train_selection()` do the carve; `meta.json` gains
  `selection_examples` and `selection_slice_fraction`, drops `val_examples`
  / `val_source`.
- `training/train.py`: reads `prepared/selection.jsonl` (was
  `prepared/val.jsonl`); local naming (`selection_ds`, `has_selection`)
  updated to match what the set actually is now.
- `training/tests/test_selection_slice.py`: new — guards the split is a
  true partition, membership is content-keyed not position-keyed, and
  `resolve_source_files()` never re-admits the real tier.
- No change to `evaluate_real.py`, `datasets/real_validation.jsonl`, or
  `datasets/real_holdout.jsonl`.
- Does not retroactively invalidate the 2026-09-02 training run — that
  checkpoint was already documented as superseded for other reasons
  (overfitting, pre-copy-ratio-fix corpus).

## Approved by

- Product Owner — chose option (a) directly when the review's finding was
  surfaced, and declined splitting the real 15 for the reason above.
- Engineering Lead (Claude) — implemented per the chosen option; verified
  the split against the live 525-record corpus (44 of 525 carved into
  selection, ~8.4% against the 10% target) and confirmed all existing
  tests plus new ones pass before this was written up.
