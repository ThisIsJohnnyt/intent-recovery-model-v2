# PDR-013: Narrow exception to the content-safety boundary — sanitized self-harm context, narrative-only

**Date**: 2026-09-11
**Status**: Accepted

## Decision

[PDR-005](PDR-005.md)'s prohibition remains **permanent and unchanged** for what it was actually written to stop: no content **depicting a method, instructing, or normalizing** self-harm, suicide, or violence toward oneself or others is ever permitted in this project's data, at any tier, under any circumstance. That is not being reopened.

This PDR adds one narrow, explicitly-scoped exception, layered on top of that unchanged prohibition, not a replacement for it: a small number of **hand-authored-only** training examples may exist whose `input` includes a passing, **non-graphic, state-naming mention** of self-harm ideation or comparable acute distress (e.g., naming that the thought occurred, never depicting how) embedded in an otherwise ordinary note — for the specific and only purpose of teaching the model a section-specific behavior:

- `narrative` may retain the content, in sanitized/non-graphic form if the input itself wasn't already non-graphic — treated as legitimate emotional/cognitive context, consistent with `GOLD_PHILOSOPHY.md`'s existing "Human-Centered Intent Recovery" principle (state is fair game; diagnosis is not).
- `bullets` and `action_items` must **never** carry this content, in any form, regardless of how the input phrases it.

Constraints on this exception, all required, not optional:
1. **Hand-authored by the product owner only.** Not Gemini-generated, not generated by any other model or automated pipeline. This category stays under direct human judgment end to end. Stated plainly rather than overstated: this constraint is not mechanically enforceable, the same way `DATASET_SPEC.md` already concedes it cannot verify that `real_validation.jsonl` is genuinely hand-authored — a provenance field would not fix this, since anything that produces the content could also produce the field. The dedicated file (constraint 4) is the strongest structural control available, not a technical guarantee; this ultimately rests on the same trust basis the real-tier data already does.
2. **Never graphic, never instructional, never method-specific**, in either the `input` or any `output` field. If an authored example drifts into depicting method, it is discarded and rewritten from scratch — identical remedy to PDR-005's existing rule for any other drift into this territory, not a lesser standard because it's now a permitted category.
3. **A new, dedicated `category` tag**, not reused from the existing taxonomy — this teaches a content-boundary judgment, not a structural/linguistic pattern, and needs to be trivially identifiable and auditable as its own set, separate from the rest of the corpus.
4. **Lives in its own file**, proposed as `datasets/self_harm_context_boundary.jsonl` rather than interleaved into `datasets/synthetic.jsonl` — same schema, same pipeline intake, but isolated so this specific, highest-sensitivity category can be reviewed, audited, counted, or pulled entirely on its own, independent of the rest of the corpus.
5. **Deliberately small.** Enough examples for the model to learn the pattern, not a meaningful fraction of the corpus. Exact count is the product owner's call at authoring time, not fixed here.
6. **Explicit carve-out from the existing cross-field consistency check, in every place it's stated.** Both `DATASET_SPEC.md`'s consistency rule and `REVIEW_GUIDE.md` §4 ("Fields must agree with each other" — "a disagreement about the same fragment means at least one of them is wrong") say the same thing in two places, and both are correct for every other category and exactly backwards for this one. `narrative` carrying content that `bullets`/`action_items` omit is the *entire point* of these examples, not a defect. This needs to be stated as an explicit exception in both documents, not left for a reviewer (human or Gemini) to infer, or every example in this category will be incorrectly flagged as broken by the exact checks meant to protect everything else.

## Reasoning

### The eligibility gate comes first, and it is what actually keeps this narrow

This exception exists because of `GOLD_PHILOSOPHY.md`'s existing "Human-Centered Intent Recovery" principle, not despite PDR-005 — that principle already treats cognitive/emotional state as fair game everywhere else in this corpus ("rushed, distracted, excited"), and already draws the line at diagnosis, not at feeling. A passing mention that a difficult thought occurred is state. A method is not state — it is exactly the "depicting... instructing... normalizing" PDR-005 and PDR-001 exist to stop. That distinction is the entire gate, and it does not bend based on how much training signal would help produce a more reliable model. **No argument in this PDR, about open-weights guarantees or anything else, extends this exception one inch past that gate.** Method-specific self-harm content, or any other category PDR-005 names, remains permanently ineligible regardless of what training would or wouldn't guarantee about it — the question "would training on X make the model more reliably safe" is never, by itself, sufficient reason to include X. It is necessary but not sufficient; eligibility under Human-Centered Intent Recovery is the actual, separate, non-negotiable filter, and it was already true of every other category in this corpus before this PDR existed.

The product owner's own framing during the discussion this PDR is based on: *"emotion is not intent, but emotion is context."* A journaling or voice-dictation use case that cannot represent that a difficult thought occurred isn't a safer tool — it's a worse one at the actual job this project exists to do.

### Why this needs to be trained, not just observed or filtered downstream — verified, not assumed

Two findings support why an exception is needed at all, now, rather than relying on what already happens:

**The current checkpoint's inference-time behavior on this content is real but demonstrably unreliable, and the corpus contributes nothing to it.** The 2026-09-11 adversarial probe session ([docs/reviews/2026-09-11-adversarial-probe.md](../reviews/2026-09-11-adversarial-probe.md)) found `action_items` clean of this content in 12/12 outputs (against 4/12 reaching `action_items` on the retired flan-t5 checkpoint), and `bullets` consistently non-graphic. But `narrative` was inconsistent — at least one output retained graphic, method-specific language verbatim in narrative while the same output's bullets sanitized it. Checked directly against `DATASET_SPEC.md`'s hard content boundary (a complete exclusion, not "graphic banned, state-naming permitted" — the existing 532-record corpus contains zero examples of this content in any form): nothing in this project's training data could have taught any of the behavior observed, reliable or not. It's inherited from Qwen3.5-4B's base pretraining/alignment, not earned by this project — encouraging as a starting point, not something this team can tune, explain, or guarantee survives a future base-model or training change.

**Separately, this project ships open-weights, which limits which fix is even available.** Application-layer filtering (a post-processing step stripping this content from `bullets`/`action_items` in a wrapper application) would work for any deployment the product owner controls, but this project's license permits anyone to load the raw checkpoint directly, bypassing any wrapper entirely — unlike a closed-API product, there is no single door to enforce a guarantee at. This explains why *if* a guarantee for already-eligible content (state, per the gate above) is wanted, training is the mechanism available and application-layer filtering alone is not. It is not an argument for what content is eligible to train on in the first place — that question is answered above, and only above.

### A separately-discussed defense-in-depth idea, now resolved as moot

A prior session raised inference-time input screening (a check on the raw note *before* it reaches the model, independent of the model's own trained behavior) as a defense-in-depth idea, motivated by an early adversarial probe against the then-current flan-t5 checkpoint: 0/12 clean outputs, distressing content reaching `action_items` in 4/12 — the model did nothing to filter or soften it. That finding is what drove the decision to rebase onto a stronger model rather than pursue a screening layer (PDR-012's migration to Qwen3.5-4B). Revisited 2026-09-11: the rebase already resolved the specific failure the finding measured (`action_items` now 12/12 clean, per the probe cited above), and the narrower problem that remained (`narrative`'s inconsistency) is what this PDR addresses directly. The input-screening idea's own motivating evidence no longer holds against the current checkpoint — closed as superseded by events, not left open.

### Why this doesn't erode PDR-001/PDR-005's original reasoning

PDR-001's motivating concern, and PDR-005's extension of it into a permanent rule, was specifically about self-harm **instructions and method depiction** reaching an output — the exact thing named in litigation against OpenAI. This exception is scoped to never touch that: no method, no instruction, no normalization, in any field, ever — identical to the existing rule, just with an explicit, narrow allowance for naming that an emotional state exists.

### The ideation-vs-method line, made explicit

Constraint 2's "never method-specific" is easy to under-apply in practice, because a phrase naming a specific method often reads as no more graphic or dramatic in tone than a compliant ideation-only phrase — the miss isn't about intensity, it's mechanical. Found in practice, 2026-09-12: several of the product owner's own hand-authored draft examples named a specific method despite reading no more dramatic than compliant ones, because the difference isn't in tone. The test, stated directly so it's checkable rather than a judgment call each time:

**Does the phrase describe a feeling/wish/thought occurring, or does it name an act, tool, or means?** Naming a feeling or wish, with no means attached, is ideation — eligible. Naming any act, tool, method, or means — however briefly, however casually stated, however low-key the surrounding sentence reads — is method-specific and ineligible, full stop, regardless of tone.

Illustrative only, not drawn from any corpus file (kept generic so this section stays safe to read/reuse without pulling flagged content back into scope):

- Eligible (ideation, no means named): "thoughts about hurting myself," "wish I didn't have to be here anymore," "thinking about a way out of this."
- Ineligible (names a means, even briefly): "thoughts about cutting," "wish I could just [specific method]," any phrase naming a specific act, tool, or means by which self-harm would occur.

This is the same remedy as the rest of constraint 2: discard and rewrite from scratch, keeping the state-only shape, dropping the named means entirely — not softened, not paraphrased, removed.

## Scope

- **Unchanged, permanent:** the depiction/instruction/normalization ban, in full, at every tier, exactly as PDR-005 states it. This PDR narrows nothing about that prohibition.
- **Not retroactive.** The existing 532-record `datasets/synthetic.jsonl` corpus is unaffected — it was built entirely under the unamended rule (procedurally: the generation prompt instructs declining and regenerating any example that drifts into this territory), so nothing in it requires review, edit, or regeneration because of this PDR. `datasets/real_validation.jsonl` (15 records) and `datasets/real_holdout.jsonl` (12 records) are hand-authored by the product owner directly and were never subject to that generation-prompt exclusion, so they needed a separate check — done: a keyword scan across all 27 records for self-harm/suicide-adjacent language found no matches. That's meaningful evidence, not the same category of guarantee `synthetic.jsonl` has procedurally — a keyword scan can miss idiosyncratic phrasing a generation-time instruction can't produce in the first place. If either file is ever found to contain such content later, that's a separate, retroactive question this PDR does not resolve in advance.
- **Newly permitted, narrowly:** the category described above, under all six constraints, in a new dedicated file.
- **Requires updates to, before any example is authored under this PDR:**
  - [`docs/vision/GOLD_PHILOSOPHY.md`](../vision/GOLD_PHILOSOPHY.md) — eighth principle amended to reference this PDR's exception, same pattern as PDR-005's own original edit to that principle.
  - [`training/DATASET_SPEC.md`](../../training/DATASET_SPEC.md) — hard content boundary section gets the exception's exact terms; cross-field consistency rule gets the explicit carve-out from constraint 6 above.
  - [`docs/datasets/TAXONOMY.md`](../datasets/TAXONOMY.md) — new category defined.
  - [`docs/datasets/REVIEW_GUIDE.md`](../datasets/REVIEW_GUIDE.md) — §0 hard-gate check updated to recognize the narrow exception rather than blanket-reject on sight, **and** §4 ("Fields must agree with each other") gets the same explicit carve-out as `DATASET_SPEC.md` — found missing from the first draft of this PDR, caught in Gemini review.
  - `training/prepare_data.py`'s `resolve_source_files()` — currently hardcodes `datasets/synthetic.jsonl` plus a `datasets/gold/gold_v*.jsonl` glob; verified directly, it will not automatically pick up `datasets/self_harm_context_boundary.jsonl` without a small, explicit addition to that function.
- **Does not, by itself, trigger a retrain.** Authoring examples under this PDR and incorporating them into a future `prepare_data.py`/`train.py` run are separate, later decisions.
